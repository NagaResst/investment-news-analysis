## 📄 核心文件说明

### 1. index.json（索引文件）

**位置**：`投资新闻归档/index.json`

**作用**：
- 记录所有 summary 文件的元数据
- 提供快速检索入口
- 维护基金与日期的映射关系

**文件结构**：
```json
{
  "version": "1.0",
  "last_updated": "2026-05-03T18:30:00",
  "total_summaries": 45,
  "funds_tracked": ["003984", "005827", "006567"],
  "summaries": [
    {
      "date": "2026-05-03",
      "file_path": "2026-05/2026-05-03/summary_2026-05-03.md",
      "funds_mentioned": ["003984", "005827", "006567"],
      "key_events": [
        "央行宣布降准0.5个百分点",
        "宁德时代发布Q1财报",
        "新能源补贴政策延期"
      ],
      "item_count": 15,
      "created_at": "2026-05-03T18:30:00"
    },
    {
      "date": "2026-04-26",
      "file_path": "2026-04/2026-04-26/summary_2026-04-26.md",
      "funds_mentioned": ["003984", "005827"],
      "key_events": [
        "国务院常务会议部署稳增长措施",
        "白酒消费税改革传闻"
      ],
      "item_count": 12,
      "created_at": "2026-04-26T19:00:00"
    }
  ]
}
```

**字段说明**：
- `version`：索引文件格式版本
- `last_updated`：最后更新时间（ISO 8601格式）
- `total_summaries`：summary 总数
- `funds_tracked`：跟踪的基金代码列表
- `summaries`：summary 列表（按时间倒序）
  - `date`：日期（YYYY-MM-DD）
  - `file_path`：相对路径
  - `funds_mentioned`：涉及的基金代码
  - `key_events`：关键事件列表
  - `item_count`：单条 summary 数量
  - `created_at`：创建时间戳

**更新规则**：
- 每次生成新的 summary 后，必须更新 index.json
- 添加新条目到 `summaries` 数组开头
- 更新 `last_updated` 和 `total_summaries`
- 如出现新基金，添加到 `funds_tracked`

### 2. summary_YYYY-MM-DD.md（每日汇总报告）

**位置**：`投资新闻归档/YYYY-MM/DD/YYYY-MM-DD/summary_YYYY-MM-DD.md`

**作用**：
- 汇总当日所有重要信息
- 提供核心指标速览
- 记录基金动态和市场事件
- 保持 Markdown 单文件归档，不额外生成 HTML 页面

---

### 3. 投资建议报告（HTML）

**位置**：
- `投资者行动/持仓分析与建议/web/投资建议报告_YYYYMMDD.html`

**作用**：
- HTML 版本作为历史验证、浏览和分享的唯一归档文件，便于在桌面和手机上阅读

**约束**：
- 章节顺序必须一致，至少覆盖一至七章
- HTML 中的「七、本次建议摘要」仍是后续自动验证的唯一解析来源
- 第四章不建议使用超宽横向大表，优先使用分基金卡片、定义列表或分组块展示信号
- 第二章优先写“先看这三件事”，第三章集中解释为什么这样排优先级，第四章只保留逐只基金的处理办法
- 第五章优先放预测复盘、风险雷达、重点盯防对象，第六章优先放下周观察点和政策新方向，避免信息跳来跳去
- 第四章必须一只基金一张卡片，不得把两只基金合并成一个共用建议块
- 第四章的单基金卡片至少包含：当前建议、什么时候动作、判断理由、事实依据、信息边界
- 判断理由负责讲结论，事实依据负责讲证据，信息边界负责讲数据缺口、反向证据或失效条件，三者不要混写成一个段落
- 事实依据优先使用当天 summary 已出现的 2-3 条硬信息：量化数据、政策/产业事件、ETF 资金流、横向比较结果
- 正文中的基金名称可增加悬浮卡片，悬浮展示基金名称、代码、净值、总金额、占比；但第七章摘要表保持纯文本，不依赖 hover 或脚本解析

## 📅 目录组织规则

### 1. 按月份归档

**规则**：
- 每月创建一个文件夹：`YYYY-MM/`
- 例如：`2026-04/`、`2026-05/`

**优点**：
- 避免单个文件夹文件过多
- 便于按月统计和分析
- 符合时间序列逻辑

### 2. 按日期归档

**规则**：
- 每日创建一个文件夹：`YYYY-MM-DD/`
- 例如：`2026-04-26/`、`2026-05-03/`

**优点**：
- 清晰的时间线
- 便于回溯特定日期
- 支持按日查询

### 3. 文件命名规范

**Summary 文件**：
```
summary_YYYY-MM-DD.md
```

**单条 Summary**：
```
{三位序号}_{标题关键词}.md
```
- 序号从001开始递增
- 标题关键词：提取核心词汇，去除特殊字符
- 例如：`001_宁德时代Q1财报.md`

**原始数据文件**：
```
fund_{基金代码}_{数据类型}.json
policy_{日期}.json
stocks/{股票名称}.json
```

## 🔄 文件更新流程

### 日常更新（每个交易日）

**步骤**：

1. **创建当日目录**
   ```bash
   mkdir -p "投资新闻归档/2026-05/2026-05-04"
   mkdir -p "投资新闻归档/2026-05/2026-05-04/item_summaries"
   mkdir -p "投资新闻归档/2026-05/2026-05-04/raw_data/stocks"
   ```

2. **搜索并保存数据**
   - 执行搜索策略（参见 [search-strategy.md](search-strategy.md)）
   - 每轮搜索后立即保存：
     - 原始JSON → `raw_data/`
     - 单条 Summary → `item_summaries/`

3. **生成每日 Summary**
   - 汇总当日所有信息
   - 生成 `summary_2026-05-04.md`

4. **更新 index.json**
   ```python
   import json
   
   # 读取现有索引
   with open('index.json', 'r') as f:
       index = json.load(f)
   
   # 添加新条目
   new_entry = {
       "date": "2026-05-04",
       "file_path": "2026-05/2026-05-04/summary_2026-05-04.md",
       "funds_mentioned": ["003984", "005827"],
       "key_events": ["事件1", "事件2"],
       "item_count": 12,
       "created_at": "2026-05-04T18:30:00"
   }
   
   index['summaries'].insert(0, new_entry)
   index['last_updated'] = "2026-05-04T18:30:00"
   index['total_summaries'] += 1
   
   # 写回文件
   with open('index.json', 'w') as f:
       json.dump(index, f, ensure_ascii=False, indent=2)
   ```

5. **提交到 Git**
   ```bash
   git add .
   git commit -m "归档 2026-05-04 投资新闻（12条信息）"
   git push
   ```

## 📊 数据检索方法

### 1. 通过 index.json 快速定位

**场景**：查找某基金在特定日期的 summary

**方法**：
```python
import json

def find_summary(fund_code, date):
    with open('index.json', 'r') as f:
        index = json.load(f)
    
    for summary in index['summaries']:
        if summary['date'] == date and fund_code in summary['funds_mentioned']:
            return summary['file_path']
    
    return None

# 使用
path = find_summary("003984", "2026-05-03")
if path:
    print(f"找到：{path}")
```

### 2. 通过文件系统搜索

**场景**：查找包含特定关键词的单条 summary

**方法**：
```bash
# Linux/Mac
grep -r "宁德时代" "投资新闻归档/2026-05/" --include="*.md"

# Windows PowerShell
Select-String -Path "投资新闻归档\2026-05\*.md" -Pattern "宁德时代"
```

### 3. 通过原始数据分析

**场景**：重新处理历史数据

**方法**：
```python
import json
import glob

# 读取某段时间的所有基金数据
files = glob.glob("投资新闻归档/2026-04/*/raw_data/fund_003984_*.json")

all_data = []
for file in files:
    with open(file, 'r') as f:
        all_data.append(json.load(f))

# 进行分析
print(f"共读取 {len(all_data)} 个数据文件")
```

## ⚠️ 注意事项

1. **目录一致性**：
   - 严格遵循目录结构
   - 不要随意更改文件命名规则
   - 保持 index.json 与实际文件同步

2. **文件完整性**：
   - 每次生成 summary 后，立即更新 index.json
   - 确保 raw_data 和 item_summaries 对应
   - 定期检查文件是否缺失

3. **版本控制**：
   - 使用 Git 管理所有文件
   - 每次更新后提交
   - 编写清晰的 commit message

4. **备份策略**：
   - 定期备份到云存储
   - 保留至少3个月的历史数据
   - 重要数据多重备份

5. **权限管理**：
   - 确保文件读写权限正确
   - 避免多人同时修改同一文件
   - 使用锁机制防止冲突（如需要）
